# Stage 6 — comparator (preamp + PMOS-input StrongARM + NAND SR latch)

Schematic: `xschem/comparator.sch` (generated by `xschem/gen_comparator.py`; sizes and reasoning there).
Drawing: `material/schematics/stage6_comparator.png`. Run: `./run.sh`.

## Design

- **Preamp (added in integration I2):** PMOS-lvt pair 4/0.5, 4 µA tail from `pbias`, diode-connected
  nfet 0.5/1 loads (gain ≈ 2). It isolates the DAC top plate from the latch's clocked kickback (see below).

- **PMOS (lvt) input pair 4/0.5:** the DAC top plate moves within ≈ 0.1 … 1.3 V around vcm ≈ 0.72 V
  (switching scheme in `sim/inmux/README.md`). A PMOS pair works down to 0 V.
- StrongARM: tail pfet 4/0.15 (gate clkb), cross-coupled pfet/nfet 1/0.15, four nfet reset switches.
  Reset while clk = 0, evaluate while clk = 1.
- **op/on → identical inverters → NAND SR latch.** The first version drove a NOR latch directly from
  op/on. Its input capacitance depends on the stored state, which gave state-dependent decisions at 1 mV.
- q = 1 when inp > inn. It's held during reset, and the SAR logic samples it on the next rising clk edge.

## Results (tt, 27 °C, 1.8 V)

See `results.md` (with the preamp): 0.59 ns decision at 1 mV (A10 ≤ 50 ns), all 1 mV decisions correct at
CM 0.2 / 0.6 / 1.0 V, toggle point within ±0.5 mV, kickback peak on a floating 2.4 pF input 0.02 mV
(was 3.4 mV without the preamp), 3.9 µA (preamp bias).

## Why the preamp was added (found in integration I2)

Without the preamp, the first full-ADC run showed a constant −2 LSB offset. At the clock edge the
StrongARM tail turns on and the input pair's gate capacitance couples the same charge onto both inputs.
In the ADC, `vtop` reaches ground through the DAC caps *and* the ~kΩ bottom-plate switches, while
`vcm` sits directly on its decoupling cap. So in the first ~0.3 ns `vtop` moved +5 mV and `vcm` +3 mV. The
latch decided inside that ≈ 9 mV differential transient. The stage 6 test used ideal-source inputs and
couldn't show it. With the preamp the latch's kick lands on two identical preamp output nodes (common mode)
and barely reaches the inputs.

## Simulation notes (apply to every comparator / ADC run)

1. **Tolerance:** with ngspice's default reltol (1e-3) and a 0.1 ns step, about 10 % of the 1 mV decisions came
   out wrong. That was numerical: a 5 ps max step, or reltol 1e-5 with an adaptive step, gives all-correct
   decisions. The testbenches use reltol 1e-5 (32 s instead of ~5 min for a 5 ps cap).
2. **Threads:** `.spiceinit` now uses `num_threads=1`. Two parallel runs with 4 threads each slowed down ~15×.
3. Offset (A7) and noise (A8) are Phase 2 items (Monte Carlo and transient noise).

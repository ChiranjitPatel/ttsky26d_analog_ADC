# Stage 8 — cap_dac (8-bit binary MIM DAC) + dac_sw (bottom-plate switch)

Schematics: `xschem/dac_sw.sch`, `xschem/cap_dac.sch` (both generated by `xschem/gen_dac.py`).
Drawing: `material/schematics/stage8_cap_dac.png`.
Run: `ngspice -b tb_dac.spice > ../out/dac/tb_dac.log; ngspice -b tb_dac_hold.spice > ../out/dac/tb_dac_hold.log; python3 report.py`

## Design

- 128 + 64 + … + 1 + 1 (termination) = 256 unit caps, cap_mim_m3_1 2 × 2 µm (9.30 fF) → 2.38 pF.
  Top plate (c0) on `vtop`; bottom plate (c1, met3, larger substrate parasitic) on the switched node.
- dac_sw per group: TG to `vadc` (smp = 1); pfet_lvt 4/0.35 to `vref` (smp = 0, b = 1); nfet 1/0.15 to
  VGND (smp = 0, b = 0). Gate drive: NOR(smp, b) and NAND(smpb, b).
- The vref switch is lvt because vref = 1.215 V leaves a regular pfet only ≈ 0.2 V of overdrive.
  pfet_01v8_lvt has no model below L = 0.35 µm (the first version used L = 0.15 and failed to load).

## Phase 1 results (tt, 27 °C, 1.8 V; ideal vref / vcm / vin)

See `results.md`: all 256 codes stepped with a binary counter of pulse sources, one per µs. Gain 1.00000,
offset +1 µV, DNL 0.001 LSB, INL 0.0007 LSB, settled to 1.3 µV within 0.1 µs, top-plate leak ≈ 0.6 pA.
(A first run at default tolerance showed DNL 0.10 / INL 0.13 LSB: all of it numerical.)

## Simulation finding: default tolerance creates fake settling tails

With ngspice's default reltol (1e-3), every node (even static gate nodes) showed a slow µs-scale
"settling" of ~0.5 mV, which looked like a leak on the floating top plate. With reltol 1e-5 the nodes
are exact; the real top-plate leakage is ≈ 0.6 pA (−12.5 µV in 50 µs), negligible even for the
10 µs-per-bit slow-clock modes. Very small absolute tolerances (abstol 1e-14) make ngspice abort
("timestep too small") in the switch body nodes; abstol 1e-12 / vntol 1e-7 is enough.
These rules are in CLAUDE.md.
